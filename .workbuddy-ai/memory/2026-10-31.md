## Device Excel export: flowchart status as 0/1 + totals row

`lib/services/export_service.dart` → `exportDevices()`:
- Flowchart step cells were `✔`/`✘` text; now written as **numeric** `IntCellValue(1/0)`, blank (`TextCellValue('')`) when the step is unknown/legacy null.
- After the last device row a **`جمع` row** is written: label in column 11 (آدرس), one total per flowchart column, bold + thin top border (`flowSumStyle`).
- Totals are plain numbers, **not** `SUM()` formulas: the `excel` package writes `<f>` with an empty `<v>`, and viewers that don't recalc on open would show 0.
- Verified with a throwaway `dart run` harness against `assets/export.xlsx`: values and totals round-trip correctly (harness deleted afterwards).

## Pack form details: internal device code range (کد داخلی) — display only

Requirement was clarified: **nothing is sent to the backend** and nothing is editable. The range is *derived* from the `code` values the form's devices already carry (`"code": "271"`) and only shown in the form-details view.
- `inventory_form_data_class.dart`: top-level `formatDeviceCodeRange(Iterable<String>)` + `InventoryFormItem.deviceCodeRange` getter (computed from `devices`). Consecutive numeric codes collapse to `start-end` at a run of 3+; runs of 2 stay `271, 272`; non-numeric codes are appended as-is. `271..280 + 282` → `271-280, 282`.
- `form_details_view.dart`: `_DeviceCodeRange` banner at the top of the «دستگاهها» section, shown only when the derived range is non-empty. Value rendered LTR (`TextDirection.ltr`) so ranges keep their order inside the RTL layout.
- An earlier iteration added an editable `code_range` field + payload key to `pack_form_modal.dart`; it was **fully reverted** (the user explicitly did not want anything sent). No API/model field exists for this — do not reintroduce one without being asked.
- Formatting verified with a throwaway `dart run` harness covering contiguous/singleton/duplicate/alphanumeric/empty cases (deleted afterwards).

Note: the repo is not `dart format`-clean (pre-existing style), so new code follows surrounding style instead of running the formatter.

## Inventory forms Excel export — split by day

New file `lib/services/inventory_forms_workbook.dart` (pure Dart: `excel` + `shamsi_date` + model, **no Flutter imports**, so it can be exercised with `dart run`). `ExportService.exportInventoryForms` only saves the returned bytes.

Workbook layout:
- Sheet «خلاصه»: title band, subtitle (Jalali timestamp, form/day counts), 9-tile KPI strip, then one row per day (date, Persian week day, forms, packs, parts, returns, devices, install items, merged internal-code range) + grand total + footer note.
- Sheet «فرمها»: 22 columns with all form data (`_formColumns`), then per day a merged banner row (`پنجشنبه • 1405/06/12 • 2 فرم • 13 دستگاه • … • کد داخلی: 271-280, 282`) followed by that day's rows; grand-total row at the end.
- Days newest-first; undated forms go to a trailing «بدون تاریخ» block (gray banner).
- Counts are real numbers (`IntCellValue`), amounts are `DoubleCellValue` with `NumFormat.custom('#,##0.##')` so Excel shows separators without "number stored as text" flags. Row heights estimated from the longest wrapped value (cap 4 lines).

Gotchas learned (important):
- **`excel` 4.0.6 drops `Sheet.isRTL` on save.** The workbook is therefore re-zipped (`archive` package) and `rightToLeft="1"` injected into each `xl/worksheets/sheet*.xml` `<sheetView>`.
- `flutter test` is unusable in this sandbox (flutter_tester WebSocket fails) → verify via `dart run` harnesses against the pure builder.
- `setColumnWidth` takes `double` (a `List<int>` of widths fails to compile).
- `TextCellValue` is not `const`.
- `shamsi_date` was added as a direct dependency (already transitive via `persian_datetime_picker`) for Jalali week-day names.

UI: «خروجی اکسل» button added to the inventory toolbar (`inventory_management_tab.dart`), tinted secondary style next to «فیلتر», spinner while exporting, success/error toasts. `InventoryProvider.exportFormsToExcel()` now returns the exported count and **fetches the remaining pages first** (`_fetchAllForms`, dedup by id, 200-page guard) so the export covers all forms, not just the loaded page; the client-side search is applied to the full set.
