# 2026-10-28

## Fixed Android release build (was failing)

**Symptom:** `flutter build apk` would not produce a build. Root cause was a Gradle/AGP/JDK version deadlock:
- Only JDK available is Android Studio's JBR **25** (no JDK 17/21 installed).
- Wrapper had been bumped to Gradle **9.8.2** (download stalled at 169 MB, never completed) while AGP was **8.7.3** — AGP 8.7.x does not support Gradle 9.x.
- Gradle 8.12 (the original wrapper) cannot run on JDK 25 either, so simply reverting the wrapper was not an option.

**Fix applied (all in `android/`):**
- `gradle/wrapper/gradle-wrapper.properties` → `gradle-9.1.0-all.zip` (already present in the local Gradle cache, supports JDK 25).
- `settings.gradle.kts` → AGP **8.11.1**, Kotlin **2.2.20** (both fully cached locally; AGP 8.11.1 is the first line that works with Gradle 9).
- Release signing was missing entirely (`android/key.properties` did not exist) → generated `android/upload-keystore.jks` (alias `upload`, pass `shooka2026`) + `key.properties`. Both are gitignored.

**Result:** `build/app/outputs/flutter-apk/app-release.apk` (68 MB, versionName 2.3.5, versionCode 1) builds in ~3m45s, installs and launches on the `Medium_Phone_API_37.0` AVD without crashes.

**Known follow-ups:**
- Flutter 3.47.8 warns AGP 8.11.1 / Kotlin 2.2.20 "will soon be dropped"; the aligned target is AGP 9.1.0 + Kotlin 2.4.0 + Gradle 9.3.1. Not done because the Gradle 9.3.1 distribution download stalls on this network (GitHub-hosted).
- On launch the app shows its own server-driven "update available" dialog because the build reports 2.3.5; that string is not in `lib/`, so it comes from the backend.
- Stale `~/.gradle/wrapper/dists/gradle-9.8.2-all/*.part` (169 MB) can be deleted to reclaim space.

## Release signing wired to the real keystore

The throwaway keystore I generated was removed; the project now signs with the user's own key:
- Keystore: `android/my-release-key.keystore` (JKS, single entry, alias `my-key`, cert `CN=Sepanta Shafizadeh`, issued Oct 2025).
- `android/key.properties` — `storeFile=my-release-key.keystore`.

**Gotcha to remember:** `app/build.gradle.kts` resolves `storeFile` with `rootProject.file(...)`, and rootProject is `android/` — not the repo root. So `storeFile=../my-release-key.keystore` silently points at the wrong place and fails with "keystore not found". Bare filenames are correct.

Verified: rebuilt APK cert SHA-256 = `e6088e23...025ab9`, matching the keystore. Both `key.properties` and the keystore are gitignored.
